## 처리한 데이터 품질 문제 4가지

### 1. 지번이 문자열 `'nan'`으로 저장되던 버그 (248건)

`pandas`의 결측(NaN)은 **float이라 `if not v` 검사를 통과한다.**
f-string에 그대로 넣으면 `'nan'`, `'산nan'`이 저장된다.
상세 페이지에 "공흥리 nan"이 노출될 뻔했다.

`clean_str()`을 만들어 모든 문자열 컬럼에 적용했다. 문자열 컬럼에 쓰기 전에 반드시 통과시킬 것.

### 2. 매핑에 없는 지목부호를 그대로 저장하던 문제

`가`(247건), `2`(1건)가 지목으로 저장됐다. 지번이 결측인 특수 레코드(가지번/블럭지번)다.
매핑 실패 시 저장하지 않고 집계만 하도록 바꿨다. 화면에 `가`가 지목으로 뜨면 안 된다.

### 3. 자기교차 geometry (116건)

`ST_MakeValid`로 보정했다. 두면 `ST_Intersects` 같은 공간연산이 조용히 틀린 답을 낸다.

**주의: `ST_Multi(ST_MakeValid(geom))`만으로는 실패한다.**
`ST_MakeValid`가 폴리곤과 선분 조각이 섞인 `GeometryCollection`을 반환할 수 있어
컬럼 타입(MultiPolygon)과 맞지 않는다. `ST_CollectionExtract(..., 3)`으로 폴리곤만 뽑아야 한다.

### 4. 좌표 이상치 (5건 삭제)

지평면 송현리 901·901-1·901-2·905·905-1의 위도가 **38.40**으로 찍혀 있었다.
양평군(37.36~37.67)에서 약 100km 북쪽이다. 원본 데이터 오류로 판단해 제거했다.
남겨두면 지도에 엉뚱한 위치로 표시되고 초기 bbox 계산까지 망가진다.

## 면적 계산 검증

원본 면적(A13)이 1.14%에만 있어 geometry에서 계산했다. 정확도를 두 가지로 확인했다.

- 원본 제공값과 비교: 오차 중앙값 **0.71%**, 97%가 5% 이내 (Task 1)
- 측지 면적(`ST_Area(geom::geography)`)과 비교: **0.01% 이내 일치**

두 번째가 좌표 변환이 정확하다는 강한 증거다. 예: 단월면 산44 임야
계산값 9,067,518㎡ vs 측지값 9,066,785㎡.

**면적은 반드시 EPSG:5186 좌표에서 계산한다.** 4326(경위도)에서 `ST_Area`를 쓰면
도(degree) 단위가 나와 값이 무의미해진다.

## 재현 방법

```bash
docker compose up -d
cd etl && source venv/bin/activate
python load_parcels.py                                   # 적재 (약 4분)
docker exec -i ddotoro-db psql -U ddotoro -d ddotoro -f - < verify_load.sql
```
