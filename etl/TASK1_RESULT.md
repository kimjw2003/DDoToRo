## 핵심 이슈 1 — 면적 컬럼이 사실상 없다

`A13`(면적)은 343,121건 중 **3,922건(1.14%)에만** 존재한다.
TASKS.md Task 2 스키마의 `area_sqm`을 원본에서 그대로 가져올 수 없다.

**대응: geometry에서 계산한다.** EPSG:5186은 m 단위 투영좌표계라 면적 계산이 유효하다.

값이 있는 3,922건으로 검증한 결과:

| 지표 | 값 |
|---|---|
| 오차 중앙값 | **0.71%** |
| 오차 5% 이내 | **97.09%** |
| 오차 1% 이내 | 62.69% |

**적재 시 면적은 EPSG:5186 좌표에서 계산한 뒤 4326으로 변환할 것.**
4326(경위도)에서 `ST_Area`를 쓰면 도(degree) 단위가 나와 값이 무의미해진다.

이상치가 소수 존재한다 (최대 293% — 합병/분할 필지로 추정). 예외 처리하지 말고 계산값을 그대로 쓴다.

## 부록 — 실거래가 API 사전 검증 (2026-07-29)

인증키 유효성만 확인했다. 수집(Task 3)은 착수하지 않았다.

```
GET .../getRTMSDataSvcLandTrade?LAWD_CD=41830&DEAL_YMD=202606
→ HTTP 200, resultCode 000 OK
```

Task 3에서 반드시 처리해야 할 것 4가지:

1. **응답이 XML이다** (JSON 아님). 파서를 그에 맞게 준비할 것
2. **`dealAmount`는 만원 단위 + 콤마 문자열** — `"2,833"` = 2,833만원.
   원 단위 저장 규칙에 맞추려면 콤마 제거 후 **× 10,000**
3. ~~**지분 거래가 섞여 있어 ㎡당 단가를 왜곡한다. 집계에서 제외할 것**~~
   → **Task 3 실측으로 정정.** 왜곡되지 않으므로 **제외하지 말 것.**
   `dealArea`도 거래된 지분만큼의 면적으로 오기 때문에 ㎡당 단가는 정상이다
   (지분 215,134원/㎡ vs 일반 220,299원/㎡). 전체의 47.9%라 제외하면 표본만 절반이 된다.
   대신 **계약해제 건(`cdealType`)을 제외**해야 한다. 성사되지 않은 거래다
4. **지번 마스킹 실증 확인** — `<jibun>4**</jibun>`.
   CLAUDE.md의 전제대로 필지 단위 매칭은 불가능하다

응답 필드: `dealAmount` `dealArea` `dealYear/Month/Day` `jibun`(마스킹) `jimok`
`landUse` `sggCd` `sggNm` `umdNm`(`지평면 망미리` 형태) `dealingGbn` `shareDealingType`

`landUse`(용도지역)가 응답에 있으나 **거래 건 단위**라 필지에 붙일 수 없다. MVP에서는 사용하지 않는다.
