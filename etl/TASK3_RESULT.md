## 지번 마스킹 실증

개인정보 보호로 지번이 가려져 제공된다. 필지 단위 매칭은 **원천적으로 불가능**하다.

```
 지번 |  emd   |   ri   | deal_ym | deal_amount | area_sqm
------+--------+--------+---------+-------------+----------
 4**  | 서종면 | 문호리 | 202308  |   213000000 |   153.00
 4**  | 서종면 | 문호리 | 202308  |     8000000 |    59.00
```

읍면동(정확히는 읍면+리)까지만 알 수 있다. 반드시 지역 집계로만 사용한다.

## 처리한 문제 2가지

### 1. UNIQUE 제약이 정상 거래 1,489건을 삭제하고 있었다

처음에 `(읍면리, 계약일, 금액, 면적, 지목)`에 UNIQUE 제약을 걸고
`ON CONFLICT DO NOTHING`으로 적재했더니 19,452건 중 **17,963건만** 들어갔다.

API 응답을 직접 세어보니 **동일 조합이 응답의 7.4%에 실제로 존재**했다.

```
202308: 657건 중 동일조합 53건
  8회: 양서면 대심리 23일 170만원 3㎡ 임야
  4회: 지평면 옥현리 22일 150만원 29㎡ 도로
```

한 필지의 지분을 여러 명에게 나눠 판 경우가 대표적이며 **모두 별개 거래**다.
UNIQUE 제약을 제거하고, 재수집 시에는 **월 단위로 DELETE 후 INSERT** 하도록 바꿨다.

### 2. 지분 거래 제외는 잘못된 판단이었다 (Task 1 정정)

Task 1에서 "지분 거래가 ㎡당 단가를 왜곡하니 제외하라"고 기록했으나 **틀렸다.**

| 구분 | 건수 | 평균 원/㎡ | 중앙값 |
|---|---|---|---|
| 일반 | 9,354 | 220,299 | 144,840 |
| 지분 | 8,609 | 215,134 | 144,444 |

거의 같다. `dealArea`도 **거래된 지분만큼의 면적**으로 오기 때문에 단가가 왜곡되지 않는다.
전체의 47.9%라 제외하면 표본만 절반이 된다. **집계에 포함한다.**

대신 **계약해제 건(`cdealType`)은 제외**한다. 실제로 성사되지 않은 거래다 (1,863건).

## API 사용 시 주의

- 응답은 **XML**이다 (JSON 아님)
- `dealAmount`는 **만원 단위 콤마 문자열** — `'2,833'` → `28,330,000원`.
  놓치면 금액이 10,000배 틀린다
- `umdNm`은 `'서종면 문호리'` 형태다. `parcel.emd`와 조인하려면 **첫 토큰만** 써야 한다
- `landUse`(용도지역)가 응답에 있으나 **거래 건 단위**라 필지에 붙일 수 없다. MVP 미사용
- 호출 간 0.3초 대기, 실패 시 3회 재시도(지수 백오프)
- 36개월 수집에 약 40초 소요. 개발계정 일일 한도(보통 1,000회)에 여유가 크다
